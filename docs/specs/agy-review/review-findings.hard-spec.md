# Hard Spec - AGY Review Findings

## Goal

Document the findings and problems detected during the review of the current implementation of the Tenant Manager application, specifically focusing on UI/UX, code structure, and potential bugs generated by the initial local model.

## UI/UX & Design Issues

- **Low Contrast / Readability**: 
  - The application uses a very light background (`#F8F9FA`) and cards with white backgrounds (`White`). 
  - Many `TextBlock` elements use `Foreground="Gray"`, which on light backgrounds causes accessibility and contrast issues, making the text hard to read.
  - *Examples*: Labels in forms ("Move-in", "End Date"), table headers ("Name", "Rent", "Status"), and secondary text in lists.
- **Button Styling**: 
  - The `Button.Action` style lacks a defined background color or border in `App.axaml`. It relies purely on the default Avalonia theme, which on top of white/gray cards may appear as floating text without a clear clickable area.
- **Hardcoded Colors**:
  - The use of hardcoded colors (e.g., `#0F52BA`, `#C5221F`, `#137333`) directly in `MainWindow.axaml` bypasses Avalonia's theming engine. This prevents the application from properly supporting Dark Mode or easily adapting to custom themes in the future.
- **Layout Sizing & Truncation**: 
  - Grids have highly specific column definitions (e.g. `2*,1.2*` or `1.5*,1*,1*,1*,1*,1*,1*`) which might cause text truncation (`TextTrimming="CharacterEllipsis"`) on smaller window sizes, degrading the user experience.

## Code Structure & Technical Debt

- **Monolithic Window**: 
  - The `MainWindow.axaml` file is monolithic (over 500 lines), containing the complete UI for Dashboard, Rooms, Tenants, Contracts, and Payments inside a single `TabControl`. 
  - *Recommendation*: Split each tab into its own `UserControl` (e.g., `DashboardView.axaml`, `RoomsView.axaml`) to improve maintainability and follow better MVVM practices.
- **Lack of CompileBindings**:
  - `MainWindow.axaml` explicitly disables compiled bindings (`x:CompileBindings="False"`). While this was specified in the original MVP rules, it removes compile-time validation for data bindings, making future refactoring error-prone.

## Proposed Action Plan

1. **Improve Contrast**: Replace `Foreground="Gray"` with a darker shade or use standard Avalonia system brushes to guarantee readability.
2. **Refactor Colors**: Move all hardcoded colors to `<Application.Resources>` in `App.axaml` and use `DynamicResource` to apply them.
3. **Split UI Views**: Refactor `MainWindow.axaml` by extracting the content of each `TabItem` into separate Avalonia `UserControl` files inside a `Views/` folder.
